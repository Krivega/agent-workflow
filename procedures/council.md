# Planning и acceptance

Procedure: council
Version: 15

<!-- aw-rule council.context-01 -->
Основание: [применимость совета](../docs/quality/agent-workflow-contracts.md#применимость-совета).
Штатный вызов и формат входов принадлежат [CURRENT-CHAT](../CURRENT-CHAT.md#советники-текущего-чата).
Участник читает общий каталог и собственный профиль по путям из [дескриптора проекта](../docs/design/api-contract.md#дескриптор-подключения-cli); основной агент получает договор вызова и его результат.
<!-- /aw-rule -->

1. <!-- aw-rule council.01 -->
   До вызова определи применимость каждого ID из `council.profiles` проекта по требованиям
   и потребителям. Для каждого запиши trigger либо предметное N/A. Неизвестная применимость, пропущенный reviewer, неполный ответ
   и NOT RUN блокируют допуск. Старый selection без новых ролей требует явной переоценки;
   автоматическое дополнение N/A запрещено. Сохраняй историю и версии требований.
   <!-- /aw-rule -->

2. <!-- aw-rule council.02 -->
   Planning получает точное предложение, scope, требования и критерии до реализации.
   Локальная реализация принятого договора по ADR-0063 допускается по проверяемому плану
   исполнителя без planning-сеансов; карта применимости и независимая acceptance сохраняются.
   Неполные потребители, неизвестный риск, новое поведение или выход за область требуют planning.
   Советники работают в отдельных native read-only/never/network=false сеансах с явными
   model/effort. Штатный CLI готовит origin, полные LOAD, точное поручение и binding; неподтверждённый
   профиль, чужая история, унаследованные пишущие права и self-PASS не дают допуск. Покажи роли
   и ссылки пользователю. Обязательный native источник нельзя заменить текстом модели.
   <!-- /aw-rule -->

3. <!-- aw-rule council.03 -->
   Acceptance заново выбирает роли по фактическому изменению: точный diff/base, полные существенные
   входы, реальный baseline и evidence. Новая область требует planning затронутых специалистов.
   Фикстура и прогноз не подтверждают работающий сценарий.
   <!-- /aw-rule -->

4. <!-- aw-rule council.04 -->
   Получи scoped PASS/FAIL: источники/revisions, полное покрытие, ограничения, стабильные findings
   и условия их устранения. Открытый blocker запрещает PASS. UI/UX сохраняет отдельные design.ui
   и design.ux и фазовые доказательства по [своему профилю](../roles/ui-ux-designer.md).
   Неприменимая роль возвращает ровно N/A; обе N/A дизайнера требуют переоценить selection.
   <!-- /aw-rule -->

5. <!-- aw-rule council.05 -->
   Повтор направляй прежнему adviser: исправление, открытые замечания и новая delta. Активную роль
   ожидай без повторного создания; потерянную identity восстанавливай. Незатронутый PASS применим
   лишь при прежних scope/требованиях и полном неизменном manifest роли. Общая смена target сама
   по себе не отменяет такой PASS. Неизвестная полнота требует повторной экспертизы.
   <!-- /aw-rule -->

6. <!-- aw-rule council.06 -->
   Один correction + affected review даёт один round независимо от числа голосов и HEAD.
   Исходные FAIL/dissent сохраняются; закрытие требует evidence. Три последовательных FAIL
   ответственного reviewer следуют прежнему [арбитражу](arbitration.md).
   <!-- /aw-rule -->

7. <!-- aw-rule council.07 -->
   Механический M1 сохраняет допуск только при доказанных identity/delta/links принятого материала;
   новая семантика возвращает к planning. Завершение требует всех обязательных проверок и решений,
   отсутствия blocker/непринятого compromise и единого Result с долговечными источниками.
   Принятые дочерние области и проверки текущих профилей перед completed сохраняются.
   <!-- /aw-rule -->

<!-- aw-rule council.context-02 -->
Выход: ограниченное заключение точного предложения/изменения; оно не принимает всю задачу вне scope.
<!-- /aw-rule -->
