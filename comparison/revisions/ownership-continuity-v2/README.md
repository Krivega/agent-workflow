# H06/2 — принятая семантика, исполнение не разрешено

`semanticAccepted:true`, `mayRun:false`, `executionAuthority:none`. Пользователь выбрал target-specific семантику H06/2. Root отдельно сохраняет первичный пользовательский источник: этот пакет не создаёт source/turn/grant и не подменяет его метаданными.

Новый критерий `ownership-continuity-across-long-stage` сохраняет общую цель: прежние owner/generation/identity/workspace/scope и отсутствие повторного dispatch при долгой работе. Legacy предъявляет фактический принятый renew ДО исходного OLD deadline; затем долгий этап пересекает OLD deadline под ещё действующим продлённым lease, новый lease_until покрывает этап. Renew после expiry запрещён Store; recover-owner — отдельное восстановление, не renewal. Temporal предъявляет durable состояние/историю той же логической LocalTaskWorkflow (schemaVersion 11 выполняет ManagedTaskWorkflow), pending effect и продолжение при остановке/замене Worker и replay. ADR-0067 заменяет технический lease lifecycle, поэтому Temporal lease не добавляется и не симулируется. Исторический /1 `lease-renewed` остаётся unmet для Temporal и не получает PASS от нового критерия.

Task/stimulus H06 согласованы с этой семантикой. Остальные шесть критериев, H01–H05, лимиты suite, две пары/резерв и встроенные файлы материалов сохранены. Встроенный checks.mjs проверяет только форму manifest, не семантическую квалификацию H06. Никаких H07–H12 в исходных assets нет.

Длительность общего долгого этапа, исходная legacy lease boundary и бюджет конкретного запуска ещё не выданы. Будущий host --plan должен предъявить их как предложение, не начинать часы и не делать execute-ready или authority inference. Числа suite — прежние верхние ограничения общей серии, не разрешение нового H06 запуска. Физическая STOP, fresh identity, неизвестные эффекты, frozen/released и exact native RESUME source/target остаются отдельными обязательными границами. Без первичных native доказательств native qualification остаётся UNKNOWN, включая случай model-free PASS.

Сначала в отдельной рабочей копии реализуется test-owned H06 contract/host/checker и отрицательные тесты. Новая схема production lifecycle, технический lease и новый series planner не нужны. Действующие cli/comparisonSeries.ts, cli/comparisonReport.ts, comparisonReadiness/H01Preparation продолжают импортировать /1; переключения до полной квалификации нет. Pending candidate08 и прежние пакеты/отчёты не меняются.

Файлы consumer-map.json и profile-insertion.md — предложения интеграции для владельцев кода/документации в отдельной копии. Они не применены к основному репозиторию. Accepted-criteria-freeze.json закрепляет точные значения, хеши и границу полномочий.

Уточнение criteria-r02: r01 содержал неверный порядок «renew после boundary». Он сохранён как исторический superseded текст; для новой реализации используется только r02. Store проверяет state.lease_until > now до renew (sqliteEvidenceStore.ts:197), а новый lease_until > now — в обработчике renew (:290). Для данного сценария дополнительно требуется newLeaseUntil > stageEnd; истёкший lease не возобновляется через renew. --plan может предложить stage 35s / OLD boundary 20s / new lease beyond stage, но эти числа не выданы как длительность, бюджет или разрешение исполнения.
