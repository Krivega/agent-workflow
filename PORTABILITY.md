# Независимая упаковка и пилот

Исторические состояния и первичные
доказательства сохраняют исходные ссылки и область подтверждения. Выделение не создаёт публичный выпуск, глобальную
установку или новое полномочие на исполнение. Исторические пробы ниже сохраняют свой scope.

## Граница копирования

В нейтральный проект устанавливается самостоятельный пакет `@krivega/agent-workflow`
с явными зависимостями и минимальной конфигурацией запуска. Runtime imports используют только относительные пути внутри инструмента,
`node:*`, XState и YAML. Для запуска TypeScript нужен tsx; для договорных проверок — Vitest
и его обязательный peer Vite. Версии и полный граф берутся из фактически установленных пакетов
и сохраняются в manifest, а не подменяются последними версиями из сети.

Проектный descriptor заменяется нейтральным: отдельный project_id, свои AGENTS, plan roots,
индексы, mutable links и команда validate. Процедуры копируются побайтно с прежними hash.
Ссылки на исходные проектные решения в их основаниях сохраняют происхождение; продуктовые
модули, alias, исходные docs и абсолютный путь игры не нужны для выполнения инструмента.
Требования нейтрального проекта задаёт его descriptor, а не отсутствующие файлы игры.

Проверка выполняет CLI и договоры из новой директории, не через ссылку на исходный node_modules.
Отдельный системный запрет чтения исходного репозитория проверяется отрицательным чтением
и положительным запуском CLI, миграции и export/restore. Системные ограничения macOS на `ps`
учитываются отдельно от границы импортов; они не являются разрешением пропустить остановку
реальных процессов в обычном процессном прогоне.

## Идентичность и восстановление

При переносе меняется locator namespace, но project/task/evidence ID остаются прежними.
Export требует freeze; restore проверяет manifest, БД, blobs и полноту. Неизвестная schema
отвергается до записи. Upgrade/rollback и отключение — отдельные явные действия по
[MIGRATION](MIGRATION.md); копирование папки не даёт нового владельца, lease или права записи.

Проверки упаковки не заменяют полный допуск исходного проекта. Два теста, привязанные именно
к его архитектурной конфигурации и project_id, проверяются в исходном репозитории; остальные
договоры запускаются без изменений в нейтральной копии. Итоговая нейтральная конфигурация сохраняет исходные 5000 ms для test/hook, изоляцию
и assertions. Начальная конфигурация 30000 ms не принимается как окончательное доказательство.

## Сопоставимый пилот

Шесть классов: локальный дефект, изменение между модулями, документ, механическое применение,
потерянное подтверждение с восстановлением, native interrupt/compaction с передачей преемнику.
Каждая пара получает одинаковые исходники, требования, неизменяемый проверяющий сценарий,
профиль модели и allowlist результата. Модель действительно читает и предлагает изменения;
контроллер применяет только разрешённые файлы и запускает реальные проверки.

Обычный вариант использует свежий read-only сеанс и проверку результата. Workflow дополнительно
подтверждает LOAD, сохраняет карточку/состояние и проводит применимые независимые planning и
acceptance роли; M1 сверяет точные принятые байты. Отказы не заменяются PASS. Исправления
контроллера и моделей сохраняются с исходными журналами и входят в измеренное время.

Это ограниченные исполняемые задания на нейтральном тестовом проекте с заданными дефектами,
не пользовательская приёмка игры и не статистически достаточная оценка всех будущих работ.
Fault injection отделён от естественных ошибок. Измеряются пропуски требований, поправки,
время, раунды, доступные token usage и команды чтения. Точное число повторных чтений файлов
может быть неизвестно из-за составных команд; размер файла не заменяет токены. Денежная
стоимость без фактического тарифа остаётся неизвестной.

Исторические результаты AW11 и оценка пользы при большей стоимости ищутся через
[manifest первичных материалов](docs/evidence/README.md). Точный locator результата
в этом руководстве не закреплён; новый сравнительный PASS здесь не заявляется.
Регрессия качества блокирует включение. Даже при отсутствии регрессии пилот не обещает
экономии и не выдаёт автоматических полномочий запускать новые роли в чужих задачах.
