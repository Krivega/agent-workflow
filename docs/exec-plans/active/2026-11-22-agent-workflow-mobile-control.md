## Сводка для продолжения

Один владелец вдали от Mac хочет узнать, почему задача ждёт, а затем ответить на конкретный
вопрос. 23 ноября владелец уточнил цель: управлять всеми подключёнными проектами
и всеми их текущими и будущими задачами. Мобильный сервер использует действующий список регистраций из `worker.json` на Mac.
Владелец подтвердил способ подачи команды: «Да, сертификат и подтверждение».
Это принятие относится к проверке сертификата и явному подтверждению конкретной операции
в браузере с привязкой к проекту, задаче, запуску и редакции. Приёмка T6 и T7 идёт независимо. Штатная установка остаётся локальной.

Основание — пересмотр плана мобильного доступа от 28 октября. Вместо одновременной разработки
всех форм сначала проверить чтение с настоящего телефона. Следующее действие — выбрать
пилотную задачу и маршрут доступа, проверить вход владельца и отзыв потерянного
устройства. 23 ноября владелец создал поддомен для веб-доступа. Проверка DNS подтвердила
A-запись `agent.krivega.com` → `62.183.22.43`. По данным владельца, адрес ведёт на TNAS. Целевой сценарий — открыть адрес в браузере телефона через мобильную сеть.
Для пилота сохранить взаимный TLS до Mac. При наличии входящего адреса можно передать
TCP с порта 443 на частный адрес пилота и порт 8443. При доступности только исходящих
соединений нужен внешний узел с TCP-перенаправлением через защищённый туннель до Mac.
При таком перенаправлении узлу доступны метаданные соединения, а закрытый ключ HTTPS
и проверка сертификата телефона остаются на Mac. При проверке с рабочего хоста TLS-соединение
на порту 443 не установилось за четыре секунды. В локальной сети порт 443 на TNAS
принимает nginx. Запрос с именем пилота к TNAS получил HTTP 301 на порт 5443.
При проверке с TNAS порт 8443 на Mac отклонил соединение. Публичное правило
перенаправления на роутере ещё предстоит сверить. Критерии отказа и отзыва сохраняются.

## Этапы и критерии приёмки

### 1. Увидеть состояние задачи

- [ ] CHECK-01: на физическом телефоне через мобильную сеть владелец выбирает проект и задачу, видит
  состояние, причину ожидания и время последнего подтверждения. Сверить показания с локальным
  клиентом. При потере связи или сне Mac страница помечает данные как устаревшие; при возврате
  из фона перечитывает состояние. Зафиксировать ОС, браузер и результаты проверки.
- [ ] CHECK-02: сервер проверяет личность и доступ к конкретной задаче при каждом чтении.
  Проверить отказ для постороннего, подменённого ID проекта или задачи и отозванной сессии.
  Первый выпуск показывает выбранные поля статуса; полные журналы, произвольные файлы и
  операции записи недоступны. Из мобильной сети нет прямого доступа к Temporal API/UI,
  PostgreSQL, Docker или Codex. Проверить отключение входа с Mac.

### 2. Ответить на ожидающий вопрос

- [ ] CHECK-03: до включения записи принять ADR о том, как сервер доказывает происхождение
  удалённого решения. Привязать его к владельцу, проекту, задаче, вопросу, ожидаемой редакции
  и точному содержанию ответа. Существующий [допуск из чата Codex](../../../CURRENT-CHAT.md#запуск-через-temporal)
  сохраняет свой источник. Проверить отказ при подмене автора, расширении полномочий,
  просроченной сессии и запросе изменения с посторонней страницы.
- [ ] CHECK-04: ответ на один поддержанный тип вопроса применён ровно один раз. Двойное
  нажатие возвращает ту же квитанцию. После потерянного ответа или перезапуска сервера
  исход сверяется по прежнему ID команды. Изменённое содержимое с тем же ID и ответ на
  устаревшую редакцию получают отказ. До подтверждения эффекта интерфейс показывает
  только факт приёма команды. Неизвестный исход блокирует зависимый повтор.

- [ ] CHECK-07: владелец может поставить задачу на паузу, продолжить или отменить её
  в любом зарегистрированном проекте. Для каждого маршрута проверить состояние исполнителя,
  адресацию одноимённых задач разных проектов, повтор команды и отзыв устройства.

### 3. Поставить новую задачу

- [ ] CHECK-05: перед отправкой владелец видит и подтверждает проект, цель, границы изменений
  и бюджет. Сервер проверяет регистрацию проекта и допуск на старт. Подмена проекта или
  увеличение бюджета после подтверждения получают отказ. Повтор после потери ответа даёт
  одну задачу и один Run ID; проверить по истории Temporal и квитанции команды.

## Эксплуатация и доказательства

Temporal остаётся источником состояния исполнения. Мобильный сервис читает его и передаёт
разрешённые команды через клиентские договоры. Хост отвечает за Worker, рабочие копии
и артефакты. Администрирование Mac, терминал и выдача секретов остаются вне этой поставки.

- [ ] CHECK-06: перед включением каждого выпуска пройти затронутые локальные проверки,
  полный `yarn validate` для изменений кода и соответствующий сценарий с телефона.
  Приложить версию сборки, наблюдаемый результат и квитанции без секретов. Для отката
  закрыть внешний вход и отозвать сессии. Проверить с локального клиента, что состояние
  и история задачи сохранились, а принятое ранее поручение доступно для штатного управления.

Локальный [пилот чтения](../../../examples/mobile-control/README.md) использует штатный
`task-chat status`, регистрации проектов и сертификат телефона владельца.
Каталог перечитывает назначения из `backend-assignments` и проверяет маршрут регистрации.
В проверке каталога нужны два проекта с одноимёнными задачами и новая задача после старта. Регрессии отказа при
подмене ID, отзыва и отображения при потере связи — `node --test tests/mobileControl.test.mjs`.
CHECK-01/02/06 остаются открыты до измерений на физическом телефоне и проверки отката.
Следующий этап — перевести чтение на автономный каталог TNAS и проверить рабочий домен.
CHECK-03–05 следуют за проверкой чтения.

### Локальная проверка чтения 2026-11-23

На версии `de830ee` команда `node --test tests/mobileControl.test.mjs` прошла оба теста.
В отдельной проверке обработчик слушал loopback по TLS 1.3, получал тестовый статус
одной задачи и проверял временные клиентские сертификаты. Запрос владельца вернул 200,
запрос второго клиента с сертификатом того же CA — 403, запрос другой задачи — 404.
После удаления файла отпечатка следующий запрос владельца по тому же TLS-соединению
вернул 403. Для CHECK-01/02/06 ещё нужны наблюдения с телефона через мобильную сеть
и сверка состояния и истории зарегистрированной задачи после отключения входа.

### Проверка каталога 2026-11-23

Мобильный сервер запущен на loopback с временным сертификатом и действующим списком
регистраций Worker. Через HTTPS каталог показал оба зарегистрированных проекта.
У `neutral-example` список назначений пуст. Для `mathematical-detective` чтение списка
завершилось `backend-policy-required` (HTTP 503). Действующая политика и допуск
относятся к [рабочему переключению Temporal](2026-11-23-temporal-production-rollout.md).
Способ подтверждения решений принят в [ADR-0077](../../design/decisions/0077-confirm-mobile-owner-commands.md).

Владелец подтвердил вход с компьютера по локальному адресу `https://192.168.1.114:8443/`.
Затем владелец подтвердил вход с телефона по домашнему Wi-Fi с клиентским сертификатом.
Вход через мобильную сеть и чтение состояния конкретной задачи ещё предстоит проверить.

## Автономный каталог на TNAS

Владелец поручил реализовать Docker-поставку сайта и обновление отдельно от Mac.
Для нового маршрута TLS завершается в nginx на TNAS, Mac экспортирует последний
проверенный каталог. Ранее проверенный прямой вход на Mac сохраняется как локальный пилот.
Комплект, подготовка и откат описаны в [инструкции TNAS](../../../examples/mobile-control/tnas/README.md).
Критерий рабочего допуска — при отключённом Mac телефон открывает домен через мобильную сеть,
видит дату подтверждения, а обновление одного сервиса сохраняет каталог и проверку отзыва.

Локально собран образ linux/amd64. Проверены выдача сохранённой карточки без сети и Worker,
перезапуск, запрос через nginx с сертификатом владельца и отказ после отзыва. При проверке
Compose неисправный контейнер не прошёл healthcheck, восстановленный рабочий контейнер
прочитал тот же каталог. Отдельная проверка скрипта обновления с подменой Docker CLI прошла
ветви одобрения digest, возврата к предыдущей версии и восстановления после прерывания.
Публикация в GHCR и рабочий запуск на TNAS требуют отдельного допуска.

### Рабочее размещение 2026-11-23

По разрешению владельца комплект установлен в `/srv/agent-mobile` на томе TNAS.
LaunchAgent Mac синхронизирует каталог раз в минуту. Отдельная запись в
`/etc/cron.d/agent-mobile` проверяет одобренный digest каждые пять минут.
Системный nginx читает виртуальный хост из `/etc/nginx/agent-mobile.conf`
и обслуживает мобильный контейнер через Unix-сокет. Копия конфигурации nginx
до переключения указана в `/srv/agent-mobile/backups/initial-nginx-path`.
При продлении сертификата обновить файлы, читаемые nginx в `/etc/nginx/agent-mobile-tls`,
проверить `nginx -t` и перечитать конфигурацию.

Владелец выбрал отдельный внешний TCP-порт 8443 с переадресацией на порт 443 TNAS.
Адрес пилота — `https://agent.krivega.com:8443/`. Публичный запрос с доверенным
CA проверил сертификат сервера и получил ожидаемый отказ без сертификата телефона.
Основной внешний 443 направлен на порт 10443 общего Caddy игры.
Владелец подтвердил успешный вход с телефона через мобильную сеть по адресу пилота.
Владелец также подтвердил доступ с телефона после выключения Mac. В момент следующей
сверки снимок TNAS содержал пустой список задач neutral-example и недоступный список
mathematical-detective. Чтение карточки конкретной задачи с телефона остаётся открытым.

Опубликован и активирован [выпуск mobile-v1.0.3](https://github.com/Krivega/agent-workflow/actions/runs/45176488165).
Рабочий digest `sha256:ab54290e5da82b41725846e70f6fedba20c40321b70f729ef916a22cd16d4f54`.
TNAS скачал образ из GHCR, сверил ревизию и запустил его через штатный updater.
У контейнера статус healthy, ответ каталога на внутреннюю проверку — HTTP 204.
