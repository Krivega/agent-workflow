# Рабочий цикл инструмента

## По наблюдаемым данным

До изменения определи результат, владельца правила, потребителей, сохранённые данные и
проверки. После достаточной проверки переходи к действию; повторное чтение связывай с новой
неизвестностью. Объединяй независимые чтения, показывай итоги и ошибки вместо полных журналов.

Не смешивай исторический PASS и текущее поведение. Любой scoped отчёт перечисляет исходники,
версии, эффекты, остановки, неизвестное и то, что он не квалифицирует. Зависимое действие
ждёт своего входа/первичного доказательства; безопасная независимая работа продолжается.

## Совместная работа

При разрешённом параллельном исполнении назначай короткий scope и непересекающиеся файлы.
Каждый агент сохраняет чужие изменения. Интегратор сверяет актуальный общий результат, а не
повторяет всю работу независимого исследователя. Завершённого агента будит followup task,
обычный send message только доставляет сообщение.

## Завершение

Выполнить согласованный результат целиком, применимые проверки и независимое ревью существенной
границы. Не объявлять закрытыми оставшиеся собственные критерии плана. Новый внешний эффект,
приостановка полномочий или архитектурное исключение требуют применимого решения пользователя.
Технический долг имеет одного владельца в [реестре](../exec-plans/tech-debt-tracker.md).

## Уровни проверки

Уровень выбирается по изменению смысла. Для смешанной правки применяется самый строгий
затронутый уровень; состав проверок и полномочия остаются у существующих владельцев.

| Изменение | Проверка |
| --- | --- |
| Оформление, опечатка или ссылка без изменения смысла | `yarn lint:docs`, существование цели и якоря, сравнение смысла до и после; `git diff --check` |
| Правило или маршрут работы без изменения полномочий и условий допуска | Предыдущий уровень, обычный, пограничный и неприменимый примеры; доступность владельца правила |
| Код, исполняемый договор, полномочия или состав обязательных проверок | Применимые профильные проверки и полный `yarn validate` с четырьмя показателями покрытия 100% по [стратегии](../testing/strategy.md#обязательная-граница) |

Упоминание тестов в тексте само по себе не требует запуска кода. Текстовая проверка не заменяет
проверку изменённого поведения или обязательный полный допуск при изменении кода. Markdown
проверяется markdownlint и проверкой ссылок; отдельное форматирование Markdown через Prettier
не применяется. Эти уровни не выдают полномочий на установки, службы или другие внешние действия.
