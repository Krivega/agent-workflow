# H06: первичное подтверждение опубликованного предложения по ссылке

Это отдельный экспериментальный источник допуска `/4` для Temporal H06.
[Первичное поручение](primary-approval.json.gz) пользователя следует за готовым предложением
с точным JSON и прямо разрешает считать отдельное сообщение присланным и продолжать.
Сохраняются настоящий текст пользовательского ответа, его нативный источник и ссылка
на предшествующее предложение. Пользовательский JSON или запись в журнале не создаются.

## Границы решения

Приёмка остаётся `h06-autonomous-recovery/3`: один ограниченный прогон включает
начальный длительный Writer, PAUSE, тёплый RESUME, вторую PAUSE, холодный RESUME
и отдельный завершающий Writer. Ручной `/2` и буквальный JSON-допуск `/3` сохраняют
свои прежние входы и проверки. Производственные NativeUserCommands и NativeReaderAuthority
не получают нового источника.

Новый вход полномочий `comparison-h06-temporal-reference/4` явно закрепляет старое
опубликованное предложение. Новый внешний запуск имеет kind
`comparison-h06-temporal-reference-run/4`, пакет — profile `h06-reference-temporal/4`.
Эти входы не принимаются маршрутами `/3`. Уже проверенный родительский допуск использует
прежнюю исполнительную обвязку `/3` с отдельным доказательством источника `/4`.

## Проверяемое согласие

- Источник — настоящее пользовательское сообщение текущего исходного чата и активного
  хода, с пользовательским происхождением в нативном журнале. По умолчанию оно должно
  быть последним; ниже закреплён один точный случай отдельного ответа о кеше.
- Полный текст должен совпасть с явно поддержанным поручением продолжать и считать
  отдельное сообщение присланным либо точным «запускай»/«Запускай» с необязательным одним LF.
  Короткая форма подтверждает один прогон только после законченного предложения ниже;
  «продолжай», цитаты, отрицания, пересылки и дополнительные фразы не принимаются.
- Непосредственно предшествующее сообщение ассистента должно быть завершённым `final_answer`
  из того же чата и содержать ровно один буквальный JSON старого предложения и ссылку
  на его закреплённый файл.
- Старый JSON сверяется с предложением, исходным запросом, серверными параметрами и бюджетом.
  Он остаётся предложением ассистента; пользовательским источником служит настоящий ответ.

Перед настоящим H06-ответом допускается максимум одно точное пустое уведомление об
изменении блоков от обвязки, из того же хода и журнала. Оно не заменяет предложение
или согласие; его ссылка сохраняется в `proposalNoticeSource`. Два уведомления,
настоящие изменения, другое происхождение или другое сообщение сохраняют отказ.

Нативное сжатие контекста может повторить `turn_context` внутри того же хода. Только `/4`
перед проверкой продолжения исключает такой повтор из временного представления, если
весь payload совпадает с первым контекстом этого хода, а после предыдущего контекста
есть нативная запись `compacted`. Без этой записи или при любом изменении payload
повтор остаётся и отклоняется прежней проверкой. Журнал, первичные ссылки и сохранённый
префикс не изменяются; остальные проверки выполняются над исходными записями.

Отдельный поздний ответ про npm не отменяет уже данное согласие H06. Только `/4`
распознаёт точную пару: пустое уведомление об изменении блоков от обвязки и настоящий
ответ «Очистить только кеш npm» на вопрос
`call_c6e9621816a141bc8f63a955e9e0faea`, индекс 0. Проверяются весь текст,
пользовательское происхождение ответа, происхождение уведомления от обвязки,
тот же активный ход, точные вопрос и варианты и исходная завершённая запись вызова
с SHA-256 `2f2bb40cb52a247d07b76cf256ca0c1a2a3ac76e4c907ef8d02672776616c846`.
Исходный допуск, его источник и ключ однократности сохраняются; последнее сообщение
проверяется отдельно как наблюдение текущего чата. Обе дополнительные записи и ссылка
на вопрос входят в доказательство. Любое другое последующее сообщение пользователя
отклоняется. Эти записи не создают и не возобновляют разрешение H06.

## Ограниченный перевод runtime

Новый wrapper, архив исполнения и доказательства хранятся отдельно. Оперативные workspace,
evidence и server roots прежнего предложения остаются прежними и до первого допуска
должны быть неиспользованными. Все 22 авторских файла сохраняются побайтно.

Запросы сравниваются полностью. Изменяются только закреплённые runtime-файлы механизма
подтверждения: Authority, Run, Package и новый ReferenceApproval, README и первичное
основание этой ревизии. Список жёстко задан реализацией и не поступает из входных данных.
Двоичные файлы, Workflow, оперативный код, профиль модели, стимул, пути, бюджеты,
роли, проверки и область записи совпадают. Новый requestHash и производный serverSetupHash
вычисляются обычным способом; старые хеши не подменяются.

Новый проверенный базовый пакет может уже содержать часть или все три файла ревизии.
Тогда добавляются только ещё отсутствующие известные файлы, включая допустимый случай
нулевого добавления. Все три обязательны в текущем runtime; уже закреплённые helper/docs
должны совпадать побайтно. Неизвестные добавления и замена этих закреплённых файлов
отклоняются. Исправления оперативного кода сначала входят в новое базовое предложение
и новый численный допуск; перевод по прежнему предложению их не разрешает.

Перед запуском независимое ревью проверяет точные изменения исходников и пары старых/новых
SHA: изменения Authority/Run/Package должны касаться только этого источника допуска.
Общие часы, остановка, повторы, модельные вызовы и контроль бюджета не меняются.

## Однократность и доказательство

Резервирование использует тот же ключ настоящего пользовательского источника, что `/3`.
Новый каталог или хеш не дают повторного бюджета. После FAIL или неизвестного исхода
уже начатой попытки допуск не возобновляется. Отказ до резервирования источника и открытия
часов сохраняется отдельно и не означает начатую попытку. Историческое чтение повторно проверяет источник, предложение,
доказательство перевода и первоначальные абсолютные часы.

Подготовка не расходует источник. Перед первым живым вызовом обязательны адресные
проверки, четыре метрики покрытия 100%, полный `yarn validate`, независимое
ревью и свежая сверка pins. Пакет подготовки имеет `claimIssued:false`, `mayRun:false`.
Если подходящий источник уже получен, до дорогого полного прохода
`observeH06TemporalAutonomousSource` проверяет весь путь наблюдения настоящего текущего
чата. Это тот же читающий шаг, который вызывает consume,
без резервирования, файлов допуска, открытия часов, сервера или модели.
Пакет для нового согласия готовится без подмены отсутствующего источника; перед
живым запуском читающая проверка всё равно обязательна. После неудачной попытки
короткий ответ на новое готовое предложение создаёт новый отдельный допуск, а не
возобновляет прежний ключ.
Живые результаты не заменяются локальными тестами или replay; ручная приёмка, restore,
RPO/RTO, полная стоимость попытки и T6 сохраняют собственные критерии.
