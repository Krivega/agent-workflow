# Сценарии квалификации и измерений Temporal

Отказы, совместимость историй и методика измерений применяются к открытым критериям
[плана миграции](../exec-plans/active/2026-10-27-agent-workflow-temporal-migration.md#критерии-приёмки).
Команды выбираются в [профиле проверок](profiles/agent-workflow.md), общий допуск —
по [стратегии](strategy.md). Матрица не является разрешением сервисного или модельного запуска.

## Проверки и измерения

### Матрица обязательных отказов

| Граница | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| Temporal/Worker | Падение до шага, после эффекта до completion, перезапуск сервера | Восстановление; нет слепого повторного внешнего эффекта |
| Codex | Потерянные create/send/completion, busy session, неверный профиль, сжатие | Прежняя identity либо unknown; доказательство LOAD и результата |
| Команды | Дубликат ID с тем же/другим содержимым, stale revision, гонка Update/Signal; RESUME со служебным источником, чужими project/task/run/target или расширением scope | Один результат либо явный конфликт; сохранена редакция; неполномочный RESUME отвергнут до записи |
| Владелец | Два Workers, старое поколение, потеря сети, живой дочерний writer; восстановление с другим owner/generation, unknown, незавершённым прежним ходом, frozen/released или подменой workspace | Нет двойной интеграции, ложного stop или передачи scope при восстановлении; недопустимое продолжение запрещено |
| Отмена | До старта, в ходе модели, во время проверки, перед интеграцией | Нет новых действий; реальные stop receipts; поздний ответ не принят |
| Ёмкость и управление | Все места длительных Activities заняты; приходят pause/cancel/новая редакция; несколько проектов и Workers одного хоста | Команда не ждёт окончания модели; stop/reconcile доступны в пределах профиля T0b; общий ресурсный предел соблюдён |
| Подготовка и приёмка | Нет обязательного входа, провален preflight, пакет неполон; исправление одной роли, общий договор, открытый FAIL | Ноль зависимых дорогих запусков до готовности; новый ход/reuse каждой роли имеет предметное основание |
| Данные | ENOSPC, повреждённый blob, отказ проекции/индекса, неполный backup | Нет ложного PASS; исходные данные доступны; явное восстановление |
| Версии | Несовместимый Workflow replay, старый descriptor, смена Worker, Continue-As-New | Управляемое обновление либо отказ без новой модели/потери команды |
| Переход | Потеря ответа при регистрации backend, повтор зарегистрированной задачи под новым ID, пишущий вход Legacy после включения Temporal | Неизменное назначение backend; конфликт или отказ до эффекта |
| Восстановление | Падение на границах диаграммы 5, отстающая копия, попытка продолжить Temporal-задачу старым runtime | Сверка эффектов и восстановление в Temporal; unknown сохраняет паузу; один владелец, новые факты сохранены |
| Портируемость | Чужой root, неизвестная команда, разные проекты/роли, недоступен исходный repo | Изоляция; подключение через договор; отсутствие скрытых зависимостей |
| Границы runtime | Новая Activity импортирует старый сохраняющий lifecycle-сценарий; журнал эффектов принимает стадии/таймеры/решения совета | Архитектурная проверка или схема отвергает второй контроллер; совместимость остаётся только у legacy adapter |

Сначала существующие чистые policy-тесты и адресные Activity-тесты, затем Temporal
integration/replay/time-skipping tests, затем процессные FS/Git и настоящий Codex.
Тесты SDK не доказывают остановку внешнего процесса. Основание —
[инструменты проверки Temporal](https://docs.temporal.io/develop/typescript/best-practices/testing-suite).

### Истории предыдущих версий для replay

Для TEMP-11 в T2/T3 сохранять представительные истории уже выполняемых сценариев:
обычное завершение, ожидание человека, отмена, потерянный ответ, повтор команды и исправление
замечаний. В T4 связать их с исходной версией Worker и совместимой сборкой, в T5 использовать
для квалификации обновления. Истории получают из существующих разрешённых прогонов или
синтетического стенда без модели; это не повод для дополнительной платной серии.

Replay новой сборки на её собственной свежей истории не заменяет проверку совместимости:
изменённый Workflow проверяется на историях предыдущей поддерживаемой версии, включая
незавершённое ожидание. Для версии, оставленной на прежнем Worker, проверяется продолжение
на закреплённой сборке; несовместимая новая версия не получает её задачи. Фиксируются
происхождение истории, хеш и ожидаемый маршрут версии. Истории не перезаписываются новой
генерацией при неудаче replay; чувствительные данные не попадают в общий набор фикстур.
Отсутствующий сценарий отмечается как непроверенный, без переноса PASS другого сценария.
Эта конкретизация использует существующие integration/replay/time-skipping проверки и
критерий TEMP-11; состав этапов, бюджет и условия допуска не расширяются.

Команды реализации принадлежат `package.json`. При добавлении самостоятельного пакета
объявить его build/test/validate и корневые делегирующие команды в том же изменении;
не оставлять фиктивные команды в этом плане. Фактический состав команд сверяется с текущим
`package.json`. Для оставшейся работы применяется [единый порядок приёмки](../exec-plans/active/2026-10-27-agent-workflow-temporal-migration.md#единый-порядок-приёмки-без-повторных-прогонов):
адресные проверки, затронутые типы/lint/архитектура, применимый пакетный
`yarn comparison:h06:preflight`, затем один полный `yarn validate` на неизменном срезе
до живой квалификации. Отсутствие моделей в preflight не разрешает его сервисные действия.
Новый полный прогон после изменения кода и затронутая живая приёмка выполняются по действующей
стратегии; состав допуска и четыре порога покрытия 100% сохраняются. Пригодный PASS используется
только для доказанно неизменных входов и применимой среды; неизвестный исход не становится допуском.
Для этой подготовки документов: `yarn lint:docs`, `yarn lint:adr`, проверка оформления,
локальных ссылок и сохранности диаграмм.

Сравнение использует существующие шесть классов заданий из `comparison/` и одинаковые
исходники, критерии, модели/effort, лимиты и условия среды. Каждый вариант работает на своей
копии. Старую остановленную П1-серию не возобновлять автоматически; её бюджет не наследуется.
Новый бюджет и число пар фиксируются до запуска. Исторические непроверенные числа из EFF-01
не становятся baseline; недоступные журналы другого компьютера остаются TD-047.

Отдельно измеряются: время до принятого результата; время модели/очереди/инструментов;
число model calls и уникальных внешних действий; токены без кэша/из кэша/выход; исправления
после приёмки; байты history/artifacts/backups; восстановление после сбоя; объём оставшегося
собственного runtime. Инфраструктурная стоимость учитывается вместе с модельной, без выдуманных
цен. При ожидании 10 минут должно быть ноль модельных вызовов для проверки статуса.

Первый полный B1 в T3 уже сохраняет эти показатели по своему обязательному прогону:
подготовка, исполнение, проверки, приёмка, интеграция и повторы. Это ранняя диагностика
издержек без дополнительной платной серии и без заявления об ускорении. Сопоставимый
эксперимент и окончательное решение о пользе остаются в T5. Широкую инвалидизацию отдельных
проверок исследовать только при измеренном расходе; менять их зависимости без доказательства
полноты и сохранения обязательного полного validate нельзя.

Объём кода для TEMP-16 считать раздельно: предметные policy/contracts; сценарии Workflows;
адаптер Codex; артефакты и защита внешних эффектов; оставшийся технический runtime. Указывать
точную ревизию и состав файлов; тесты, фикстуры и сгенерированные файлы учитывать отдельно.
Удалённые строки не являются выигрышем, если ту же обязанность перенесли в другой каталог.
Для сохранённого механизма назвать потребителя и причину, почему его не покрывает платформа.
Учитывать также число обслуживаемых хранилищ/процессов, настройку, обновления и восстановление;
меньше нашего кода не обязательно означает меньше эксплуатационной работы.

Usage модели, оценку по API-тарифу, фактические платежи/лимиты подписки и инфраструктурные
расходы не смешивать. При отсутствии данных о платежах или лимитах сохранять неизвестность;
нулевой дополнительный платёж не означает отсутствие модельных вызовов и затрат времени.

Доверие к Temporal определяет выбор платформы, но не доказывает ускорение нашей задачи.
Качество и отсутствие дублей — обязательные gates. Если end-to-end не ускорился, миграция
не объявляется улучшением скорости: устраняются выявленные издержки либо пользователь
явно принимает иной выигрыш, например снижение поддержки. Процент сокращения кода не
назначается произвольно; принятие T6 требует удаления каждого заменённого механизма.
