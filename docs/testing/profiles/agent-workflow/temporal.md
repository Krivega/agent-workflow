# Temporal: SDK, жизненный цикл и нативный аудит

Подробные сценарии Workflow, управления, replay, отказов и независимого аудита. Варианты SDK с имитацией Codex и варианты с настоящей моделью имеют разные границы подтверждения.

[Выбор проверки](../agent-workflow.md) · [Обязательная граница](../../strategy.md#обязательная-граница).

Команды выполняются из корня самостоятельного `agent-workflow`. Сервисные, установочные и
native-варианты требуют собственного применимого разрешения; наличие команды не даёт допуска.
Исторические результаты и точные версии ниже относятся только к своим входам и попыткам,
не подтверждают текущую поставку и не заменяют открытые критерии миграции. Пометка
«историческая команда G» сохраняет прежнее имя команды игры, а не команду этого репозитория.

## Самостоятельная основа Temporal

Инструкция LOAD v2 сообщает существующий предел 8000 кодовых единиц UTF-16 на часть и
24000 UTF-8-байт на сериализованную строку/вывод. Части одного файла читаются последовательно,
по одной команде на отдельный вызов инструмента. Регрессия с большим экранированным Unicode
сверяет полное восстановление и hash; неверные размеры, порядок и повторные части отвергаются.
Новые reader-load хранят promptVersion 2; историческое отсутствие поля означает точный текст v1.
Проверка первичного сообщения не допускает подмену версии и не ослабляет проверку байтов.

`yarn validate` проверяет собственную сборку пакета, договоры проекта,
привязку host/workspace/owner/generation, точные входы, неизменяемые артефакты, отказы FS,
конкурирующий и неизвестный внешний эффект, профиль читающей роли и первичный LOAD/ответ.
Четыре порога покрытия остаются 100%. Архитектурные правила запрещают зависимости policy/contracts
от платформы и новых Activities от прежнего runtime. Общая чистая проверка частей LOAD вынесена
в пакет; прежний импорт сохранён через реэкспорт без изменения поведения.

`yarn build && yarn test:temporal` отдельно запускает временный настоящий Temporal,
проверяет подготовку, отсутствие входа, дубликат/конфликт старта, replay и новый Worker.
Тот же стенд проверяет LocalAdmissionWorkflow B1: точные исходники, отказ изменённого
владельца и replay успешной/отказанной истории. Модель и команды проверок не запускаются;
`admitted` не доказывает READY, реализацию или независимую приёмку.
`yarn test:standalone` выполняет независимые frozen-install/build/validate
на macOS при запрете чтения исходного репозитория. Эти команды не запускают модели.
Для настоящих процессных проверок внутри этого запрета используется внешний наблюдатель
только двух фиксированных форматов `ps`: Seatbelt запрещает setuid `/bin/ps` даже с allow-default.
Наблюдатель не принимает пути/команды и отвергает иные аргументы; отрицательное чтение исходного
`package.json`, установка, сборка и все тесты остаются внутри исходного запрета macOS.
Там же выполняются полные SDK B1/M1/substantial/correction/arbitration/initial-conflict с реальными процессами/командами и имитацией Codex.
Закреплённый cached Temporal CLI копируется при подготовке стенда; исполнение уже не читает
его из исходного дерева. Git revision отсутствующей установки обозначается `null`, а состав
runtime закрепляется per-file hashes. Новые модельные ходы не создаются.
`yarn build && yarn test:replay` проверяет закреплённые hashes десяти историй
`c19d7292`, трёх историй первого полного B1, пяти M1, семи substantial, девяти C1 и 15
native-историй A1, 12 native-историй первичного I1 и четырёх native-историй читающего клиента
0.165.0-alpha.1.2 и девяти историй отдельного аудита: всего 74 до надзора planning.
39 историй Task 7 с прежними отказами и ожиданием stop-unknown доводят корпус до 113,
включая незавершённое ожидание. Ещё 21 история Task 8 сохраняет native writing audit и
SDK full/cancel; всего 134. Проверяется совместимость текущей
сборки и отказ намеренно несовместимой. Native-истории сохраняют первичные байты; преобразование
формата SDK выполняется только при чтении. Корпус не пересоздаётся при проверке.
Та же проверка входит в независимый standalone-контур.

Точная новая версия допущена только для reader/review; пишущий host сохраняет 0.154.0.
`readerExecution`, `readerHost` и `review` проверяют обе версии, отказ неизвестной версии и
неприменимость старого PASS при смене клиента; прежний профиль сохраняет freeze/stop.
Живой пакет `temporal-native-review-8sVNXZ`: gpt-6.1-sol/medium, четыре хода в двух сеансах,
первичный LOAD/ответ и reuse без новых стартов. Он не квалифицирует native auditor/xhigh,
нового writer или фон. Первичный catalogue новой модели не заменяет эти проверки.

`yarn build && yarn test:local-task` выполняет полный LocalTaskWorkflow: изолированный writer,
настоящие исходные/итоговые команды, primary stop процессов, проверяемый diff, интеграцию,
независимую acceptance и RESULT/DONE. Только Codex имитируется. Дополнительные случаи стенда
`node tests/temporal/b1.mjs --fault=baseline|acceptance|cancel-writer|cancel-check`
проверяют отказ исходной команды/приёмки и активную отмену модели/команды с replay.
Вместо строки с `|` передаётся один выбранный случай. Новые модельные старты отсутствуют.
`yarn build && node --import tsx tests/temporal/b1.mjs --native MODEL` запускает обычный B1 на явно разрешённой модели: три хода writer и два
независимой роли; сохраняются primary LOAD/profile/stop/ответы, usage и сквозные измерения.
Все временные сервисы останавливаются. Долгие B1-тесты с настоящим Git/FS и журналами имеют
локальный предел 15 секунд; модельные/процессные дедлайны и четыре порога покрытия не ослаблены.
Первый путь запрещает изменение каталогов и автоматический захват writer после падения;
это не квалификация остальных маршрутов T3–T7 или рабочего переключения.

`yarn build && yarn test:mechanical-task` проверяет точное применение принятого материала без writer:
первичный planning, неизменность manifest/links/before/after, реальные команды, интеграцию,
отдельную acceptance и DONE; пять историй повторно исполняются. Внутренние проверки включают
создание/удаление/modes, отмену между файлами, подмену после admission, неполный LOAD planning,
поддельный complete и отклонение от принятой delta. `yarn build && node --import tsx tests/temporal/b1.mjs --mechanical MODEL` выполняет четыре читающих
хода в двух независимых сеансах; необходимый бюджет записывается перед запуском. Пишущая модель
не создаётся. Вход B1 версии 1 сохраняется; M1 использует явную версию 2.

`yarn build && yarn test:substantial-task` выполняет новое поведение через обязательный planning,
writer и отдельную acceptance всех применимых ролей. Для двух ролей это 11 simulated ходов и
семь replay, с реальными командами, процессами и файловой защитой. `yarn build && node --import tsx tests/temporal/b1.mjs --substantial MODEL`
требует записанного бюджета 11 настоящих ходов. SDK-матрица `--substantial-fault=CASE` покрывает
отсутствующий вход, planning FAIL, подмену предложения, отмену planning, baseline FAIL,
acceptance FAIL и отмену активного writer/команды. Исходные FAIL/blocked и stop сохраняются.
Внутренние проверки дополнительно подтверждают исходные modes, новый output, N/A, versioned
evidence/expectedFiles и отказ поддельного planning/final manifest без зависимых запусков.
Версия 3 фиксирует служебные поля ответа через native JSON Schema; отдельная регрессия сохраняет
отказ повреждённого primary hash. Версии 1/2 и их reuse/operation hashes не меняются.

`yarn build && yarn test:correction` проверяет вход 4: первичный FAIL, узкий writer в новой
копии, обязательные команды и интеграцию, affected review в том же сеансе и reuse неизменной роли,
затем RESULT/DONE. Все первоначальные замечания доступны по цепочке артефактов. Команды ролей
заданы неизменяемым входом; версии собственных и общих файлов включают modes. Отчёт версии 2
явно закрывает прежние finding IDs; PASS с незакрытым FAIL отвергается. Старый адресный допуск
отзывается до resume; его поздняя остановка не затрагивает новый допуск. Неизвестный resume
не заменяется новым сеансом. Внутренние проверки дополнены бюджетом, подменой истории и scope.
SDK-матрица `--correction-fault=exhausted|third-fail|cancel-correction-writer|cancel-affected`
выполняется по одному случаю и проверяет stop/replay без моделей. Бюджет допуска — один или два
раунда; третий одинаковый FAIL требует арбитража, исполнитель арбитража пока не подключён.
`yarn build && node --import tsx tests/temporal/b1.mjs --correction MODEL` требует конкретного бюджета **16** ходов для двух ролей и одной
правки. Стенд открыто добавляет запрещённый маркер после первого ответа writer, до снимка
кандидата; обе приёмки, исправляющий writer и первичные доказательства настоящие. Это проверка
реакции на содержательный FAIL; добавление маркера не выдаётся за самостоятельную ошибку модели.

`yarn build && yarn test:arbitration` проверяет вход 5: три первичных FAIL одного finding,
отдельный независимый арбитр на очереди `.arbitration`, одно проверенное направление, четвёртый
writer и приёмка прежнего reviewer; неизменный peer получает reuse. SDK: 28 simulated / 15 replay.
Профиль арбитра и N/A остальных фаз проверяются до зависимых моделей. Report 3 не является PASS,
не закрывает finding и сохраняет direction/compromise/no-decision с обязательностью дефекта,
исключением, риском, dissent и условием продолжения. Compromise требует явного scope и отсутствия
обязательного дефекта; реальные проверки и affected review сохраняются. Новый вход не меняет
истории 1–4; корпус дополнен девятью C1 до арбитража, всего 34. Стенд с инъекцией после первых
трёх writer проверяет также отмену арбитра/четвёртого writer, no-decision, compromise-held,
compromise-ready и повторный FAIL. `yarn build && node --import tsx tests/temporal/b1.mjs --arbitration MODEL` использует отдельно записанные
28 ходов. Этот стенд использует CLI `0.154.0` и переданный `MODEL` с уровнем `high`. Для рабочего Worker исходный профиль арбитра указан в [процедуре](../../../../procedures/arbitration.md). Самостоятельная проверка включает этот маршрут и
каноническую процедуру без чтения исходного репозитория.

`yarn build && yarn test:initial-conflict` проверяет вход 6: один подтверждённый первичный
конфликт до writer, независимый арбитр high и повторный planning у прежних ролей перед записью.
Первичный planning request/snapshot 6 требует report 4: blocking finding и `conflicts` с двумя
или более различными точными источниками из LOAD. Обычный FAIL без подтверждения конфликта,
неполный peer, изменённый источник и несколько конфликтов не запускают зависимого арбитра.
Arbitration request/snapshot 7 сохраняет прежний report 3, но явно задаёт первичный конфликт.
Compromise, mandatory defect, partial и no-decision проверяются прежним readiness; у initial нет
three-fail allowlist, компромисс без человеческого решения остаётся открытым. Повторный planning
использует report 2 с `resolved`, сохраняет исходный FAIL и требует всех применимых PASS.
SDK: 17 имитированных ходов, 12 replay, реальные команды/процессы и cleanup; `yarn build && node --import tsx tests/temporal/b1.mjs --initial-conflict MODEL`
требует отдельного записанного бюджета 17 ходов. Inputs 1–5 и тексты прежних первичных инструкций
не меняются. Человеческое продолжение held-решения и остальные маршруты T3 ещё не квалифицированы.

`yarn build && node --import tsx tests/temporal/native-reader.mjs MODEL` — отдельно разрешаемый обычный читающий маршрут
Codex с двумя ходами и первичными квитанциями; он пока использует прежний узкий stdio транспорт
в стенде. Живая матрица отказов/остановки и T3–T7 этим не подтверждены.

`yarn build && node --import tsx tests/temporal/native-recovery.mjs EVIDENCE_DIRECTORY` без новых модельных ходов проверяет
потерю квитанции отправки и completion на том же завершённом native-сеансе, unknown создания,
перезапуск копии закрытой тестовой БД и replay. Первичная сверка требует полного совпадения
служебного ID и текста в единственном пользовательском сообщении; подмена, отсутствие,
неполнота и неоднозначность проверяются отдельными регрессиями. Конкурирующие подтверждения
одной квитанции допустимы, разные результаты конфликтуют. Стенд запрещает новые create/send
и сохраняет исходные доказательства. Это не квалификация остановки активного процесса,
потери всего журнала, Update/Signal или промышленного backup/restore.

Новые контуры описаны в [договоре пакета](../../../README.md).
Обязательный полный `yarn validate` сохраняется. Отсутствующие возможности и допуски
учитываются в [плане миграции](../../../exec-plans/active/2026-11-23-temporal-production-rollout.md).

Управляемая читающая роль имеет отдельную версию Workflow. Модульные проверки подтверждают
точную редакцию/target/автора/hash, запрет RESUME без человеческого источника, повторы и конфликты,
отзыв разрешений, отбрасывание позднего результата, unknown остановки, подмену/утрату рабочей копии
и карточки, общий предел ходов, завершение хоста и гонку выдачи разрешения при остановке.
Ошибочный Update отвергается как ApplicationFailure, сохраняя работоспособность workflow.

`yarn build && yarn test:control` проверяет настоящий SDK: два проекта делят один модельный
слот, занятый до прерывания; отдельный Worker принимает управление. Проверяются pause/resume/cancel,
повтор/конфликт/устаревшая команда и replay с исходным Workflow ID. Native Codex и человеческий
источник здесь явно имитированы, модельных ходов нет.
Тот же стенд теряет журнал отправок вместе с effects, затем весь каталог полномочий,
проверяет повреждение и восстановление точных байтов. До восстановления результат остаётся
blocked, активный имитированный ход не объявляется остановленным и не повторяется.
Внутренняя запись полномочий версии 2 закрепляет список и hashes отправок до внешнего действия;
версия 1 отвергается без автоматического обновления. Это не перенос активного исполнения.
`yarn build && node --import tsx tests/temporal/native-cancel.mjs MODEL` требует разрешённого профиля: не более одного нового
хода, первичные `inProgress` до команды и `interrupted` после неё, квитанция остановки, прежняя
identity и replay. Сервисы останавливаются после проверки. Этот прогон по исходному допуску
не квалифицирует RESUME из другого чата или восстановление после потери всего журнала.

Native-проверяющий модуль человеческой команды отдельно проверяет source schema, доверенные
путь/чат/cwd/версию, UTF-8 и полноту transcript, исходное пользовательское сообщение и успешную
выдачу с точным ID/hash/source. Мутации каждого target-поля, редакций, действия, попытки и источника
не используют старую выдачу. Отвергаются служебный/чужой/пустой источник, выдача до пользователя,
неуспешный или чужой CommandExecution и новое поручение перед выдачей. Действительная выданная
команда сохраняется после следующего хода источника. Обязательный источник проверяется до отзыва
или выдачи разрешения существующим получателем.

`yarn build && node --import tsx tests/temporal/native-resume.mjs MODEL GRANT_FILE` требует оставшегося согласованного бюджета
и реального native-источника. Пауза первого LOAD, отдельная выдача RESUME в другом существующем
чате, проверка человеческого происхождения, повтор доставки, второй LOAD с прежними identity,
owner/generation/requirements/workspace, последующая отмена и replay проверяются на настоящих
Temporal и Codex. Стенд допускает максимум два старта и безопасно останавливается по тайм-ауту.
Полное чтение/ответ после RESUME и промышленный backup/restore этим не подтверждаются.

Адресные пакеты используют отдельный ReviewWorkflow и ReaderInput версии 2. `review.test.ts`
проверяет полный выбор ролей, причины, неизвестность, отсутствие произвольных лимитов,
структурированный ответ, границы preparation/LOAD/creation/report, всю объявленную цепочку
истории и первичный thread/read. Локальная правка повторяет только затронутую роль, общий файл
— обе; последняя FAIL и частичная проверка не становятся reuse, удаление записанных
предшественников отвергается. В финальном пакете снова проверяются свежесть, независимость
сеансов и ответы. Отмена, неполнота и FAIL не означают complete=true.
`yarn build && yarn test:review` проверяет реальный parent/child SDK-путь с имитацией
Codex: scoped LOAD, reuse, ранний отказ до дочерних работ, parent cancellation с подтверждением
остановки, отказ одного ребёнка при занятом соседнем поручении и replay всех захваченных историй.
Родитель отменяет остальные поручения и ждёт их подтверждённого завершения даже при ошибке.
Модель не запускается. Это технический допуск;
семантическую полноту карты утверждает её владелец, native-квалификация пакета остаётся отдельной.

`yarn build && node tests/temporal/review.mjs --bounded` проверяет ограниченный маршрут двух ролей
и неизменный reuse на настоящем SDK с имитацией Codex: четыре имитированных хода, затем ноль новых.
`yarn build && node --import tsx tests/temporal/review.mjs --native MODEL` запускает тот же ограниченный маршрут
с настоящим Codex и требует отдельного допуска: максимум четыре новых `turn/start`, effort medium,
не более 45 минут ожидания, два независимых сеанса только для чтения во временном проекте.
Сохраняются первичные LOAD/структурированные ответы, usage, manifests и replay; общий бюджет
проверяется на границе хоста и транспорта. FAIL не вызывает автоматического расширения бюджета.
Сервисы останавливаются. Этот допуск не подтверждает B1, RESULT/DONE или всю аварийную матрицу T2.
Обычные native-v2 LOAD/ответы двух ролей и неизменный reuse прошли 2026-10-28:
четыре старта, четыре replay-истории, повтор без новых ходов. Первичные доказательства,
измерения и ограничения записаны в плане.

## Продолжение и архив основной задачи Temporal

`yarn build && yarn test:continuation` и `yarn build && yarn test:requirements` проверяют вход 10: исходный FAIL,
подтверждённый stop, отдельный human RESUME, неизменную identity, повтор/конфликт команды,
полное перепланирование и DONE. Модель и authority имитированы, FS/Git/checks и Temporal —
настоящие. Входы 1–9 и прежние истории сохраняются; native нового grant не заявляется.

`yarn build && yarn test:finalization` проверяет независимый архив после DONE с отдельным action/grant и принятым
inventory; lost response сверяется без второй copy. `yarn build && yarn test:finalization-cancel-before` подтверждает
отсутствие copy до наблюдённой отмены, `yarn build && yarn test:finalization-cancel-after` — сохранение уже завершённой
copy, `yarn build && yarn test:finalization-timeout-cancel` — nonCancellable unknown и read-only reconcile. В последнем
только fixture меняет timeout на 1 с; replay выбирает этот interceptor по сохранённой метке.
Terminate очищает disposable тест после выхода Activity и не закрывает unknown как PASS архива.
Standalone включает все шесть новых SDK-маршрутов; runtime/src/dist во время прогона заморожены.

`tests/temporal/taskBudgetProcess.test.ts` проверяет реальное аварийное завершение
отдельного Node-процесса после durable reserve/capture физического бюджета. Восемь
последовательных дочерних процессов (каждый до5с) проверяют неизменный credit prefix,
идемпотентный повтор, исходный limit/binding и отказ при rewind/подмене inode.
Фикстура завершает SIGKILL только себя; модели, SDK, службы и новые зависимости не нужны.
Это component process-loss и резерв квоты, не доказательство оплаченного хода, потери
Temporal Worker или возобновления настоящего writer. Тест входит в обычный Vitest/validate.

## Аварийные проверки Temporal

Одинаковые исходные инвентари историй хранятся один раз в
`tests/temporal/histories/sources/<sha256>.json`. Первичные manifests сохраняют свои байты,
исходные имена, происхождение и хеши. `historySources.mjs` разрешает такое имя через ожидаемый
хеш и проверяет размер и байты; повреждённый общий источник не заменяется другой копией.
`node --test tests/temporal/historySources.test.mjs` проверяет обычное чтение и отказы;
`yarn test:replay` использует тот же читатель при воспроизведении сохранённых историй.

После принятого автономного H06/3 оставшиеся маршруты выбираются по
матрице продолжения.
Нормальное завершение не повторяет deadline-пробел TD-054. Процессные регрессии
`comparisonH06NativeTemporalProcesses`/`ServerSetup`/`Transport` проверяют отдельную
cooperative-очистку и принудительную остановку; подставной transport не квалифицирует native STOP.
Input11 `task-execution-sdk.mjs --self-test` и `--contract-smoke` не запускают SDK/сервер/модель;
его `--run`/`--run-can` и native-сценарии учитываются отдельно.

`yarn build && yarn test:crash` принудительно завершает отдельный процесс Worker
после внешнего completion и потерянного ответа send, переподключает клиент и восстанавливает
прежний scope только после проверки мёртвого PID, полного immutable-инвентаря и первичных
терминальных ходов. Сохраняются прежние сеанс, owner/generation и разрешения; повторных
созданий/отправок нет. Занятый сеанс отвергает второй LOAD. Потеря исхода create сохраняет
unknown без передачи scope. RPC-шлюз стенда живёт отдельно от Worker; это названная граница
этого аварийного сценария. `yarn build && node --import tsx tests/temporal/crash.mjs --native MODEL` повторяет её с настоящим Codex, четырьмя
разрешёнными ходами и сохранением usage; вариант без `--native` имитирует Codex.

В send-сценарии физический бюджет наблюдается до потери Worker, после восстановления host
до запуска нового Worker и после результата и выхода Worker. `captureTaskBudget` сверяет
прежний prefix, limit и inode по предыдущему manifest; расход не уменьшается и совпадает
с числом отправленных стартов этого сценария. Снимки сохраняются отдельно. Это наблюдение
ledger, а не разрешение восстановления или checkpoint основного Workflow. Проверка синтаксиса
стенда не заменяет его отдельный разрешённый запуск и не квалифицирует Input11/native.

`yarn build && node tests/temporal/context.mjs` проверяет отказ старого LOAD после contextCompaction,
проверенную паузу и новый LOAD в прежнем сеансе/новой попытке. `yarn build && node --import tsx tests/temporal/context.mjs MODEL GRANT_FILE`
требует фактически выданную человеческую команду RESUME; допускает три разрешённых `turn/start`
и один явный `thread/compact/start`. Успех включает первичное чтение/ответ и replay.
Имитация человеческой команды в варианте без модели не является native-доказательством.

`readerExecution`, `readerStatus`, `readerHeartbeat`, `readerRecovery` дополнительно проверяют
неизменяемую конфигурацию, диагноз из первичных данных Temporal без модели, heartbeat с
ограниченным retry прежней операции и запрет восстановления при занятом, неизвестном,
изменённом или неполном внешнем состоянии. Отказ обычного договора не повторяет Activity.
Промышленная потеря хоста/хранилища и обновление развёрнутых Workers относятся к T4/T5.

## Нативный аудитор Temporal

`yarn build && yarn test:audit` выполняет пять SDK-путей без модели и их replay:
complete/partial, первичный отказ LOAD, отмену и stop-unknown с отдельным reconcile.
Наблюдение идёт через таймеры Temporal, управление имеет отдельную очередь. Тесты audit,
auditPolicy и auditWorkflow проверяют исходный 2× без сброса, no-progress без этапа,
неизвестное время, точные refs, неправильные тип/модель/parent, неполный LOAD, compaction,
зашифрованную привязку без предположения plaintext, один final_answer после commentary,
потерю create/send/регистрационного receipt, запрет позднего старта и неподтверждённую остановку.
ReaderHost допускает этот набор только явно; reader-only recovery не освобождает native children.
Новые модули сохраняют четыре обязательных 100%, а прежние пороги не меняются.

`yarn build && node --import tsx tests/temporal/audit.mjs --native` использует CLI 0.171.0-alpha.13, вспомогательного
родителя gpt-6.2-sol/medium и нативный тип auditor gpt-6.2-sol/xhigh. До четырёх обычных
стартов и один safety reserve разрешаются только конкретным пакетом до исполнения. LOAD
процедур/профиля, независимость, фактические readOnly/networkAccess=false, единственная
доставка карточки, первичный итог и остановка родителя/ребёнка проверяются отдельно.
Неподдерживаемый профиль или неизвестный исход не заменяются другим типом/моделью.
Направление аудитора не является технической приёмкой. Отдельный AuditWorkflow сам по себе
не означает допуска рабочей эксплуатации; аудит planning основной задачи описан ниже.

Отдельный `yarn build && node --import tsx tests/temporal/audit.mjs --native-cancel` проверяет раннюю отмену native inProgress LOAD при ожидании первого
ответа: два старта, возможный третий только safety interrupt. Первичный receipt фиксирует
interrupted и stop обоих сеансов; до первого item это не proof прерывания уже работающей
команды чтения. Полный текст отчёта хранится в artifact, в Temporal передаются refs и
ограниченные coverage/direction. Корпус аудита сохраняет оба исходных Workflow FAIL.

Вход Task 7 включает аудит planning ordinary substantial с неизменной исходной оценкой.
`taskAudit`, `taskAuditWorkflow` и повторная primary-инспекция проверяют таймер во время
исходного совета, once-only claim, раннее завершение без модели, partial/четыре направления,
запрет writer/DONE до полного continue и stop, поздний исход, подмену ledger/отчёта/остановки,
неизвестное время и отмену с ожиданием обоих детей. Auditor имеет N/A в техническом совете.
`yarn build && yarn test:supervised-task` выполняет полный SDK-путь, а самостоятельный
`test:supervised-cancel` отменяет задачу при активных LOAD обоих детей. Внутреннее ожидание
намеренно задержано до первого запуска аудита, максимум на 120 секунд; внешнего ожидания нет.
Для этих проверок задайте в `AW_MAIN_MODEL` разрешённую основную модель из каталога CLI стенда `0.154.0`. Профиль отдельного аудитора закреплён в его договоре.

Native `yarn build && node --import tsx tests/temporal/b1.mjs --supervised "${AW_MAIN_MODEL:?}"` требует отдельного заранее записанного пакета до
15 стартов: 11 main на прежнем CLI/medium и четыре parent/auditor на новом CLI/medium+xhigh.
Это первый этап основной задачи; остальные стадии и no-progress/doubt остаются открытыми.

Вход Task 8 сохраняет planning и требует шесть исходных оценок: baseline, writing,
candidate-checks, integration, integrated-checks, acceptance. Общий Workflow-механизм проверяет
2× во время исходной операции, сохраняет один claim и ждёт эту же операцию после полного
continue/stop аудитора. Подмена или отсутствие любой записи этапа запрещают RESULT/DONE;
перед завершением первичные audit proofs проверяются повторно. Изменяемые файлы сохраняются
в неизменяемых blobs вместе со снимком путей; аудит не требует остановить интеграцию только
для чтения её прежних байтов. Неизвестное состояние незавершённой операции указано явно.
`stageAudit` проверяет договоры, evidence, удержание и окончательное завершение, а
`taskAuditWorkflow` — каждый таймер и последовательность этапов. Команды
`yarn build && yarn test:stage-supervised-task` и `yarn build && yarn test:stage-supervised-cancel` выполняют
полный SDK-путь и отмену при активном audit LOAD на writing. Управляемое внутреннее ожидание
завершения writer ограничено 120 секундами. Native `yarn build && node --import tsx tests/temporal/b1.mjs --stage-supervised "${AW_MAIN_MODEL:?}"`
требует отдельного пакета до 15 стартов; факт допуска записывается в плане. No-progress/doubt,
человеческое продолжение и остальные маршруты T3 остаются отдельными критериями.

Вход Task 9 добавляет явно объявленный checkpoint после подтверждённого baseline и до
первого writer. `progressAudit` проверяет no-progress/doubt, полную исходную цель и цепочку
planning/primary answers/baseline, положительное разрешение continue и stop до записи.
Причина обращения не объявляется доказанным отсутствием прогресса. У карточки timing=null:
этап, оценка и stage elapsed не выводятся из технической контрольной точки. Отдельный
taskElapsedMs принадлежит исходным часам TaskWorkflow; неизвестное значение остаётся null.
Неполный исход или другое направление сохраняются и не запускают writer. Его внешняя граница
заново проверяет квитанцию и реальный baseline, а RESULT/DONE требует ещё одной primary-проверки.
Отсутствующий запрос или evidence отвергаются при preflight до зависимых planning-моделей.

Команды `yarn build && yarn test:progress-task`, `yarn build && yarn test:progress-doubt`, `yarn build && yarn test:progress-cancel`,
`yarn build && yarn test:progress-held`, `yarn build && yarn test:progress-partial` проверяют SDK full для обеих причин, отмену при audit LOAD
и удержание до первого writer. Параллельный повтор start и изменённый payload не создают
вторую задачу или новый модельный ход. Данные запроса фиксированы до старта; этот вход не
выдаёт полномочия новому владельцу, человеческому RESUME или смене требований.
Native `yarn build && node --import tsx tests/temporal/b1.mjs --progress-no-progress "${AW_MAIN_MODEL:?}"` и `yarn build && node --import tsx tests/temporal/b1.mjs --progress-doubt "${AW_MAIN_MODEL:?}"` имеют только
заранее записанные отдельные пакеты; квалификация и расход записываются в плане.

`yarn build && node --import tsx tests/temporal/unstartedReader.mjs` проверяет native создание и stop до первого
хода без модели. Для точного unsupported CLI 0.154.0 нужны закрытый create-only журнал,
два проверенных idle headers и неизменность журнала; потерянные send/create, resume,
предыдущая история, активный/чужой header и другая ошибка остаются unknown. Поздний LOAD
отвергается до отправки. `unstartedReader-XWuOvA` сохраняет эти первичные доказательства;
старый CNj30g с unknown не переписывается.

Вход Task11 имеет отдельный `ManagedTaskWorkflow`; Inputs1–10 сохраняют прежние истории.
`yarn test:task-execution:self` проверяет запрос/план и жизненный цикл
замены Worker на двойниках, не запуская SDK. Для отдельного временного допуска подготовлены
два последовательных режима
`yarn build && yarn test:task-execution --run REQUEST.json` и `--run-can REQUEST.json`:
поздние writer/check/finish ответы, отмена при незавершённом Update, новое выполнение после
requirements и серверный Continue-As-New. Один localhost Server и два Worker за раз,
моделей/установок/загрузок0, до180 секунд с очисткой на режим. Используется закреплённый
существующий CLI1.9.1; request фиксирует новый evidence и SHA бинарника.

В SDK-драйвере настоящие Workflow/Updates/cancellation/history, но Activities, authority,
budget/checkpoint storage и ответы Review явно синтетические: qualification=false.

После подтверждённого held/drained состояния основной SDK Worker штатно останавливается
и заменяется новым; новый client повторно читает прежние run/input/held. Повторный pause
сверяет прежнюю квитанцию и отсутствие нового writer effect, затем выполняется отмена.
Это проверка замены SDK Worker, без SIGKILL процесса, восстановления внешнего writer или
нового нативного допуска. Ошибка остановки/создания/сверки не разрешает повтор writer.
Текущий `--run` включает семь базовых сценариев; прежние шесть сохранены.
CAN проверяется отдельно на новом Server с `limit.historyCount.suggestContinueAsNew=40`,
без изменения production-порога. PASS требует первичный серверный suggestion, настоящий
ContinuedAsNew, новый run, сохранённые вход/budget и отдельный SDK RESUME до новых эффектов;
неполученный suggestion не заменяется mock. Это не native grant/Task11 квалификация,
доказательство реального переноса turn credits на диске или восстановление живого writer.

Standalone запрещает чтение integration и основного checkout, использует только offline
установку, выполняет оба новых SDK-режима и сохраняет runtime tmp вне удаляемой копии.
Исходный FAIL/unknown либо ошибка экспорта оставляет копию для разбора. Старые PASS
standalone не присваиваются этому изменённому контуру; новый допуск и результат фиксируются
в основном плане.
