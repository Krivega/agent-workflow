# Договоры API инструмента

Канонические типы и парсеры находятся в `core`, `ports` и `src/contracts`; клиентские входы
и ошибки — в `cli` и `src/client`. Неизвестная/несовместимая версия останавливает запись,
а не неявно преобразуется в принятую. Проектные descriptor и role/procedure hashes проверяются
до зависимых действий. Исторические записи сохраняют свою версию; смена поставки не присваивает им новое исполнение.

[Документация SDK](../temporal-sdk.md), [CLI текущего чата](../../CURRENT-CHAT.md),
[backend и миграция](../../MIGRATION.md), [форматы хранения](../../STORAGE.md).
Публичные exports и dependency versions принадлежат `package.json`. Установленный пакет
должен проходить собственные проверки без доступа к исходному дереву игры.

## Дескриптор подключения CLI

Новый потребитель размещает `project/workflow.json` в корне своей рабочей копии. Базовый договор
версии 1 задаёт `schema_version`, `tool_version`, `project_id`, правила `rules`, идентификаторы
проверок `commands`, каталоги карточек `plans`, обновляемые ссылки `mutable_links` и версии
процедур `procedures`. Полный пример для самого инструмента — [дескриптор](../../project/workflow.json).
Дескриптор CLI и регистрация Worker в Temporal имеют разные схемы.

Новый проект явно задаёт параметры своего совета, исполнителя и проверки:

```json
{
  "council": {
    "catalog": "profiles/README.md",
    "profiles": { "architecture": "profiles/architecture.md" }
  },
  "coder_profile": "profiles/coder.md",
  "validation_commands": [{ "file": "make", "args": ["check"] }]
}
```

- `council.catalog` указывает общий каталог ролей. `council.profiles` сопоставляет каждому ID
  его профиль. Список непустой. ID начинается с латинской строчной буквы и содержит строчные
  буквы, цифры и дефисы. Имена свойств Object.prototype зарезервированы. Профиль отличается
  от каталога. Оба файла каждой выбранной роли входят в проверяемые источники и LOAD.
- `coder_profile` задаёт файл инструкций пишущего исполнителя. Пути правил, профилей и процедур
  отсчитываются от корня подключённого проекта. При использовании установленного пакета разрешён
  адрес `node_modules/@krivega/agent-workflow/roles/coder.md`. Копия исполнителя закрепляет
  правила и процедуры по содержимому; область записи по-прежнему задаёт принятое поручение.
- `validation_commands` перечисляет допустимые способы выполнить обязательный критерий
  `validate`. Каждая запись содержит непустое имя исполняемого файла `file` и массив строк
  `args`. Порядок, число и значения аргументов должны совпасть с одной записью целиком.
  В примере вызывается `make` с единственным аргументом `check`. Проект на Yarn может
  объявить `{"file":"yarn","args":["validate"]}`. Команды берутся из доверенного дескриптора
  проекта; предлагаемая исполнителем команда и его отчёт сами по себе не дают допуска.
  Соответствие проверяется при подготовке, выполнении и приёмке доказательства.

При продолжении используются закреплённый состав совета, локаторы профилей и версии входов
исходной задачи. Прежние значения по умолчанию для дескрипторов без этих полей предназначены
для уже сохранённых задач старого формата. Новые подключения описывают собственные поля явно.
