# Пакет контекста текущего чата

Подробный договор для соответствующего действия. Обычный рабочий цикл —
в [основном руководстве](../../CURRENT-CHAT.md#штатный-вход-без-json).

## Краткий контекст после сжатия

[ADR-0065](https://github.com/Krivega/agent-workflow/blob/main/docs/design/decisions/inherited/0065-assemble-compact-workflow-context.md) реализован как
отдельный договор `context_loading: fragments-v1`, LocalRun v3 / `compact-context` и квитанция
`LoadReceipt.compact`. Штатный start пока сохраняет полный LOAD: включение нового допуска
ожидает живой квалификации. Полнота 82 нормативных ID проверена независимо; найденные
в коде три P2 исправлены и приняты повторной проверкой того же агента. Для клиента
`0.164.0-alpha.11.1` отдельно проверены первичные метаданные и точное чтение ограниченного
набора; квитанция и граница этой пробы приведены в плане. Это не допуск краткого LOAD или READY.

Каждая процедура содержит нормативные блоки `aw-rule`; их упорядоченные ID перечислены
в `project/workflow.json` вместе с обычными version/hash. Пакет выбирает процедуры существующим
`selectedProcedures`, копирует блоки без пересказа и добавляет состояние из Store/ChatContext:
цель, scope, критерии, принятые решения, открытые findings и исходные FAIL, проверки,
дочерние области/результаты, pending/unknown и ближайшее запрошенное действие. Grants/intent
операций целиком не печатаются. Requested/effective профиль различаются; unknown сохраняется.

Пакет связывает текущие native `compacted` и turn, marker, роль, owner/generation, редакцию
требований, исходники и отпечаток действия. Строка чтения содержит отдельный `state_hash`:
старое чтение другого состояния не мешает свежему пакету того же действия; дубликаты
актуального пакета по-прежнему отклоняются. Служебные параметры LOAD и обновляемый `lease_until`
не создают новое действие; lease и полномочия проверяются отдельно действующим runtime.
Новый запрос или изменившееся состояние требуют свежего пакета. Старые чтения до сжатия,
другая роль/операция, обрезанный вывод, пропущенный ID и устаревшие байты не дают допуска.

Внутренний читающий вход `compact-context-chat <request.json>` с `compact_action` возвращает
пригодный пакет и состояние чтения; Store, lease, writers и советников он не меняет.
Сбой сборки сохраняет возможность полного LOAD: успешное Р1 возвращает полную квитанцию
без compact proof, даже если каталог фрагментов остаётся непригодным.
Для старого запуска это только `preview`, который нельзя принять за LOAD. Новый формат
подготовлен для основного executor; советники/coder и координация сохраняют полное чтение.
Делегирование coder от родителя v3 пока отклоняется до создания дочерней работы или изменения
формата родителя; полный путь старого родителя остаётся доступным.
Существующий запуск нельзя переводить в v3 ручной заменой поля: старые квитанции остаются
старыми, а прежние читатели отвергают новый формат.

У допущенного нового запуска штатные `task-chat load/start/continue` используют тот же
ожидающий action: сначала полностью читаются правила проекта, затем выводится одна строка
`chat_compact` с canonical content/hash. Только первичный успешный CommandExecution после
последнего сжатия подтверждает пакет. Необходимые процедуры и права проверяются прежним путём.
При непригодности по Р1 читаются полные процедуры; причина сохраняется в `compact_fallback`,
а квитанция не содержит `compact`. Это восстановление не считается успехом краткого режима.
Краткий контекст не заменяет STOP, relay, независимую приёмку и общие проверки.
