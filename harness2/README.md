# Harness²: прежние результаты и отказ новым запускам

По [плану миграции Temporal](../docs/exec-plans/active/2026-10-27-agent-workflow-temporal-migration.md#единый-порядок-приёмки-без-повторных-прогонов)
новые модельные пилоты Harness² отключены в штатной поставке. Команды `yarn harness2`,
`python3 harness2/pilot.py`, `node cli/harness2-entry.mjs`, прямые вызовы bridge,
`modelCall`, Python `run` и `Broker` возвращают `h2-new-model-runs-disabled`.
Отказ происходит до чтения входов запуска, создания транспорта, model RPC и записи
в рабочую задачу. Флага обхода нет; перенос экспериментального bridge на Temporal не планируется.
Вызов Python с `--help` показывает справку без запуска.

Первичные отчёты, FAIL/UNKNOWN и ранее израсходованные разрешения сохраняют свои границы.
Отключение новых запусков не меняет Store, задачи и их владельцев и не означает включения T6.
Исходное решение пилота сохранено в [ADR-0052](../docs/design/decisions/inherited/0052-pilot-harness2-with-agent-workflow.md).

Полноценное подключение через новый Temporal-путь описывает
[отдельный план](../docs/exec-plans/active/2026-11-16-harness2-temporal-integration.md).
Он предусматривает измерение пользы, независимую приёмку и откат принятой версии инструкции.
[ADR-0074](../docs/design/decisions/0074-integrate-harness2-through-temporal.md) пока имеет статус
`proposed`; реализация не начата, прежние входы остаются запрещёнными.

## Локальные проверки

TypeScript-проверки входят в общий `yarn validate` с четырьмя показателями покрытия 100%.
Они проверяют отказ прямому вызову модели и bridge, а также настоящий процесс CLI:
модельный исполняемый файл не запускается, исходные файлы и сохранённый FAIL остаются неизменными.
Схема прежних запросов сохраняется для проверки исторических артефактов.

Python-профиль сохраняет проверку отчётов и карт по внешнему эталону, отказ всех старых
входов запуска, отсутствие дочернего процесса и неизменность прежних файлов.
Его отдельный порог строк и ветвей остаётся 100%:

```sh
HARNESS2_PYTHON=/absolute/path/existing-python-with-coverage yarn harness2:test
```

Нужны Python 3.12–3.13 и уже подготовленный `coverage` 7.10.7. Для простого запуска тестов
без измерения покрытия: `python3 harness2/test_pilot.py`. Upstream, Codex, сеть и модели
этим проверкам больше не требуются; они не доказывают живую квалификацию прежнего пилота.

## Чтение прежних артефактов

Сохранившиеся JSON и журналы читаются непосредственно. `harness2/pilot.py` содержит чистые
`answer` и `evaluate` для проверки ответа по прежнему снимку исходников и внешнему эталону.
Они не запускают модель и не записывают результаты автоматически. Эталон — JSON-массив
записей `path`, `symbol`, `role`, `line`, `source`; роли: `contract`, `storage`, `reader`,
`writer`, `platform`, `verification`. Смысловая проверка утверждений остаётся ручной.

В историческом комплекте использовались:

- `frozen.json`, `immutable-inputs.json`: исходники, commit, upstream, модель, правила и хеш эталона.
- `calls/NN`: запрос, manifest входов, нативный журнал, проверка изоляции, ответ и ошибки.
- `runs`: исходные состояния, предложения, пробы, композиция и выбор ядра.
- `library`: экспериментальная библиотека, отдельная от памяти Codex и правил проекта.
- `comparison.json`: механическая проверка ссылок и опорных точек.
- `cancellation.json`, `stopped.json`: наблюдения отмены, которые сами по себе не закрывают unknown.

Исторический [Harness²](https://github.com/google-research/harness2) использовался без изменений,
Apache-2.0, commit `1cfe254e8d25b15f37048c3730134686abe60335`.
Результат ядра `ok` не означал улучшения, полный G2/M0 или предметную приёмку.
Публикация, очистка истории и возобновление старой операции не разрешаются этой командой.
