# Ограниченная реализация coder

Основание — [ADR-0064](https://github.com/Krivega/agent-workflow/blob/main/docs/design/decisions/inherited/0064-delegate-coder-in-isolated-copy.md).
Это дочерняя роль существующего executor; отдельные основной запуск, контроллер и Store не создаются.
Профиль участника задаёт `coder_profile` в дескрипторе подключённого проекта. Пакет поставляет [профиль coder](roles/coder.md).

## Поручение и права

Основной executor должен иметь READY, implement и наблюдаемый LOAD coordination.
В копию существующего runtime request добавляется `coder` с `action`, уникальным `id` и,
для первого `run`, объектом `assignment`: `goal`, `paths`, `files`, `checks`, `criterion`.
Пути относительны исходному workspace, `files` перечисляет явные источники и зависимости.
CLI связывает поручение с текущими task/run/session/generation, карточкой и принятым планом;
подмена или изменение поручения с тем же ID отвергается.

```sh
yarn agent-workflow coder-chat /absolute/request.json --brief
```

`run` подготавливает копию и возвращает кандидата после остановки. `status` читает состояние.
`integrate` переносит только допустимый результат. `cancel` прекращает поручение и освобождает
его область после подтверждения остановки. Повтор `run` прежнего ID передаётся без assignment;
он восстанавливает исходные операции, а не создаёт новый сеанс.

Краткий ответ содержит причину, ближайшее допустимое действие и прямые ссылки на квитанции.
`not-started` означает подтверждённый отказ до создания сеанса: дочернее поручение завершено,
его резервирование снято, повтор того же ID не запускает новую попытку. Ответ сохраняет причину
и receipt отказа. `creating` и `sending` означают незавершённую исходную операцию; `status`
показывает её устойчивый ID и ссылку на журнал. Следующий `run` передаётся с прежним ID без
assignment и только восстанавливает исходный create/send; неизвестный исход не разрешает повтор.
`cancelled` завершён без интеграции. `integrating` требует продолжения прежнего integration intent.

Резервирование ключуется canonical SOURCE root+paths. Две копии одного исходного файла конфликтуют;
разные области могут выполняться независимо. Parent locks и execution reservations сохраняются
в одной транзакции Store. Пока они открыты, REVIEW/RESULT/DONE, отмена родителя и relay запрещены.

Копия находится в `evidence_root/coder-workspaces/<id>`. В ней только явно выбранные файлы,
область записи и обязательные правила/процедуры. Git, игнорируемые файлы, известные каталоги
секретов, ключи, ссылки и hardlink не копируются. Карточка, правила хоста, профиль coder и
дескриптор процесса защищены от изменения и импорта. Файловый ACL внутри копии не обещается;
любой выход за allowlist отвергает весь результат.

Native сеанс создаётся без parent/fork и истории. Model/effort совпадают с родителем;
workspace-write/never/no-network ограничивает запись копией, включая исключение /tmp и TMPDIR.
Apps, plugins, web search, multi-agent и настроенные MCP отключаются до SDK launch.
Каталог MCP может перечислять отключённые серверы: допускаются только ожидаемые имена,
нулевые возможности и подтверждённое отсутствие работающего сервера.
Предварительный ход без инструментов подтверждает фактический managed профиль. Затем участник
читает полный LOAD; до подтверждения LOAD реализация запрещена. Requested config не доказывает права.

## Остановка и восстановление

Copy/create/send имеют устойчивые intents. Первичный native create receipt сохраняется до
возврата ответа. Потерянный ответ восстанавливается по прежней операции. Подтверждённый отказ
до create даёт `not-started` без выдуманной session. Unknown удерживает резервирование;
новый ID не служит обходом неизвестного исхода.

Завершённый модельный ход — кандидат. STOP подтверждает полную видимость терминалов и своих
процессов, остановку всех известных writers и неизменность дерева после наблюдения.
Потеря полноты не превращается в PASS от поздней пустой выдачи. Сохраняются отказ и блокировка.
Остановка всегда сверяет первичную идентичность выделенного процесса SDK и полное дерево
его потомков, включая пустую выдачу терминалов и повтор STOP. Поздний потомок запрещает
подтверждение остановки. Если SDK не сообщает OS PID терминала, это же дерево связывает его
с процессами. В runtime должен быть загружен
только этот coder; PID вместе со временем запуска сверяется до остановки. Сам процесс SDK
не входит в останавливаемое дерево writers. Неполная видимость или смена PID запрещает STOP.
Возобновление чужого или неподтверждённого активного writer запрещено. Для допродуктового
сеанса допускается восстановление исходной identity только по полному первичному доказательству:
нет LOAD/implementation delivery, наблюдаемая история пуста либо содержит единственный
завершённый профильный ход без инструментов, копия неизменна.

SIGTERM/SIGINT контроллера инициирует отмену своих операций и остановку своих writers;
PID используется только вместе с сохранённой идентичностью времени запуска.
Закрытие транспорта само по себе не доказывает STOP. После подтверждённой остановки повтор
сверяет прежний receipt, полную историю, реальные процессы и байты; уже закрытый runtime
не подменяется вновь созданным пишущим сеансом.

## Интеграция

`released` передаёт кандидата интегратору, сохраняя резервирование SOURCE. Проверяются
исходные версии всех зависимостей, scope, режимы файлов/каталогов, canonical physical binding,
фактические проверки, ошибки и stop receipt. Независимая acceptance остаётся у родителя.

До первой записи сохраняется integration intent с operation ID, parent/task/generation,
child/result/stop refs, allowlist и before/after-байтами с SHA-256 для каждого файла.
Проверяется весь набор, затем каждый шаг непосредственно перед атомарной заменой одного файла.
Удаление, создание и режим файла входят в тот же план.

При повторе прежней операции after подтверждает выполненный шаг, before разрешает оставшийся,
третье состояние сохраняет конфликт без перезаписи. Потерянный receipt восстанавливается
по тому же intent и конечным байтам; завершённые файлы повторно не записываются.
Частичный импорт удерживает блокировку. Автоматический откат поверх чужих изменений запрещён.
Отдельные проверки, общий validate и независимая acceptance закрывают родительский результат.

Новые форматы, резервная копия и откат описаны в [MIGRATION](MIGRATION.md#допуск-b1-и-ограниченный-coder-b2).
Живые права, сеть, остановка и фоновые процессы проверяются отдельно от тестовых doubles;
неподдержанная возможность остаётся NOT RUN.
