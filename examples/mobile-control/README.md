# Просмотр проектов и задач с телефона

Пилот запускается из checkout на Mac. Нужны работающий локальный `task-chat status`,
частный IPv4-интерфейс, доступный с телефона, и сертификаты для взаимного TLS.
Сертификат сервера должен соответствовать имени или IP, который откроет браузер,
и быть доверенным на телефоне. Для входа браузеру нужен клиентский сертификат владельца
с закрытым ключом. Файл `ca` на Mac содержит доверенный CA клиентского сертификата.
Доступ к порту 8443 в частной сети разрешают только устройству владельца. Маршруты и ACL
сети настраивает её владелец. Temporal, PostgreSQL и средства управления хостом телефону не нужны.

## Первый запуск с новым телефоном

Из корня checkout выполните команды на Mac. Подставьте путь к уже действующему
`worker.json`, имя сервера и LAN-адрес Mac. Каталог назначения должен быть новым.

```sh
pilot_dir="$HOME/.config/agent-workflow/mobile"
sh examples/mobile-control/setup-pilot.sh "$pilot_dir" \
  "$HOME/Library/Application Support/agent-workflow/tnas/worker.json" \
  agent.krivega.com 192.168.1.114
yarn build
node --import tsx examples/mobile-control/server.mjs "$pilot_dir/mobile.json"
```

Команда выпускает сертификаты пилота на 29 дней и запрашивает пароль для переноса на телефон.
Передайте на своё устройство через AirDrop или USB только `pilot-ca.cer` и `phone.p12`.
Установите первый как доверенный CA, второй как личный сертификат, введите выбранный пароль.
На iPhone включите доверие к корневому сертификату в настройках «Основные → Об этом устройстве →
Доверие сертификатам». На Android используйте установку сертификатов в настройках безопасности,
для личного сертификата выберите «VPN и приложения». Названия пунктов зависят от устройства.
После проверки можно удалить перенесённые файлы из загрузок телефона.

В домашнем Wi-Fi откройте `https://192.168.1.114:8443/` и выберите сертификат владельца.
Для отдельной проверки через мобильную сеть требуется согласованное правило роутера:
внешний TCP 8443 на `192.168.1.114:8443`. Отключите Wi-Fi и откройте
`https://agent.krivega.com:8443/`. После пилота закройте правило, отзовите доступ на Mac
и удалите тестовый CA и личный сертификат из настроек телефона.

## Настройка на Mac с существующими сертификатами

Сохраните JSON вне репозитория в каталоге владельца с правами 0700. Укажите фактические
абсолютные пути и адрес частного интерфейса. В `workerConfig` укажите действующий приватный
`worker.json` службы Worker. Каталог перечитывает его список `projects` при запросе. Задачи появляются в каталоге
по назначениям Temporal для этой регистрации, включая новые назначения после запуска сервера.

```json
{
  "workerConfig": "/private/host/worker.json",
  "address": "100.64.0.1",
  "cert": "/private/config/server-chain.pem",
  "key": "/private/config/server-key.pem",
  "ca": "/private/config/client-ca.pem",
  "devicePin": "/private/config/phone.sha256"
}
```

Для `devicePin` сохраните SHA-256 отпечаток клиентского сертификата, выданного телефону
владельца. Файл содержит одну строку из 32 пар шестнадцатеричных цифр верхнего регистра
с двоеточиями. Команды из корня checkout для согласованного пилота:

```sh
umask 077
openssl x509 -in /private/config/phone.pem -noout -fingerprint -sha256 | cut -d= -f2 > /private/config/phone.sha256
yarn build
node --import tsx examples/mobile-control/server.mjs /private/config/mobile.json
```

Откройте на телефоне `https://<имя-из-сертификата>:8443/` и выберите клиентский сертификат.
В каталоге выберите проект и задачу. Новый проект добавляется через штатную регистрацию Worker.
Старый конфиг с `workspace`, `registration` и `workflowId` сохраняет доступ к одной задаче.
Страница состояния обновляется каждые 15 секунд и при возврате из фона. Время на странице означает
последнее успешное чтение на Mac. Сетевой сбой сохраняет предыдущие показания с отметкой
об устаревании. Неизвестная диагностическая строка остаётся доступна через локальный CLI.

## Проверка и отзыв

1. Через мобильную сеть с частным подключением сравните проект, задачу, состояние и причину
   с `agent-workflow task-chat status --workflow-id ID --temporal-registration PATH` в проекте.
   Запишите версию checkout, ОС и браузера, время чтения и наблюдаемый результат.
2. Отключите частную сеть, вернитесь из фона, затем восстановите сеть и повторите проверку.
   Отдельно проверьте сон Mac. Убедитесь, что на телефоне доступны только согласованные порты.
3. Проверьте отказ другому сертификату, изменённым ID и POST. Для отзыва на Mac переименуйте
   файл отпечатка. При следующем чтении с прежнего соединения ожидается HTTP 403.
4. Остановите сервер через Ctrl+C и закройте сетевое правило. Повторно прочитайте состояние
   и сверьте прежний Run ID и историю через локальный клиент. Для протокола нужны фактические
   результаты с устройства. Закрытые ключи и файл регистрации в протокол не включают.

Для постоянного входа через домен предусмотрена [автономная Docker-поставка на TNAS](tnas/README.md).
