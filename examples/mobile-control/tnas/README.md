# Автономный мобильный каталог на TNAS

Mac собирает разрешённые статусы штатным клиентом. Снимок содержит ID проектов и задач,
состояния и время наблюдений. При потере связи сайт продолжает читать предыдущий файл.
Ошибка чтения проекта обозначается недоступностью списка, пустой список означает отсутствие
назначений. Для задач с недоступным статусом карточка не выдаёт подтверждение.

## Подготовка хоста

Нужны Docker Compose v2 с поддержкой `up --wait`, nginx с клиентским TLS, SSH и `flock`
на TNAS. Публикация образа и включение рабочего входа требуют допуска владельца.
Используйте на TNAS отдельный каталог `/srv/agent-mobile`. Скопируйте туда `compose.yaml`,
`receive.sh`, `update.sh`. Создайте подкаталоги и назначьте фактические UID/GID:

| Каталог | Доступ |
| --- | --- |
| `config` | Оператор пишет, контейнер читает `phone.sha256`. Скопируйте отпечаток из действующего пилота. |
| `catalog` | Учётная запись SSH на Mac пишет через `receive.sh`, контейнер читает. Назначьте группу контейнера и setgid на каталог, режим 2750. |
| `run` | Владелец — UID контейнера, группа — общая с nginx. Режим 2750, сокет создаётся с режимом 0660. |
| `tls` | Nginx читает сертификат сервера для домена, соответствующий закрытый ключ и публичный CA телефона. |

UID и GID процесса сайта задаются в приватном `.env` значениями `MOBILE_UID` и `MOBILE_GID`.
Контейнеру достаточно чтения двух каталогов и записи в `run`. Для служебного каталога
и его родителей обеспечьте nginx право прохода. Оператор хранит файлы `approved`,
`active`, `failed` и скрипты обновления в каталоге, закрытом для записи пользователю nginx.
Закрытый ключ телефона остаётся у владельца. Для отзыва удалите или переименуйте
`config/phone.sha256` на TNAS. Для самостоятельного пилота на Mac действует его собственный отзыв.

## Доставка каталога

Сначала проверьте сборку и оформите штатные регистрации на Mac. Следующая команда передаёт
первый снимок. Ключ SSH и запись known_hosts должны уже разрешать выбранное соединение.
Для отдельного ключа доставки ограничьте права учётной записи записью в каталог снимков.

```sh
sh examples/mobile-control/tnas/sync.sh \
  "$HOME/Library/Application Support/agent-workflow/tnas/worker.json" krivega@192.168.1.121 9222
```

Для автоматической отправки каждую минуту используйте LaunchAgent, запускаемый при входе
владельца. Из checkout после первой успешной передачи выполните:

```sh
worker_config="$HOME/Library/Application Support/agent-workflow/tnas/worker.json"
job="$HOME/Library/LaunchAgents/com.krivega.agent-workflow.mobile-catalog.plist"
node examples/mobile-control/tnas/sync-plist.mjs "$worker_config" krivega@192.168.1.121 9222 > "$job.new" &&
  plutil -lint "$job.new" && mv "$job.new" "$job" && launchctl bootstrap "gui/$(id -u)" "$job"
```

Для остановки отправки выполните `launchctl bootout "gui/$(id -u)" "$job"`.
Проверьте доступ к SSH-ключу из LaunchAgent. Журнал ошибок находится рядом с `worker.json`.
При ошибке
передачи сохраняется предыдущий снимок. После удаления проекта на Mac проверяйте успешную
синхронизацию. До её завершения TNAS хранит предыдущие права просмотра.

## Выпуск и обновление

После допуска на публикацию отправьте защищённый тег вида `mobile-v1.0.0`.
GitHub Actions выполняет полный validate, собирает linux/amd64, проверяет готовый образ
и публикует его в GHCR. Ограничьте создание тегов выпуска доверенными сопровождающими.
Для закрытого пакета настройте на TNAS доступ только на чтение к GHCR.
Из сводки workflow возьмите точную ссылку `ghcr.io/krivega/agent-workflow-mobile@sha256:…`.
В каталоге установки запишите её одной строкой в `approved.new` и выполните:

```sh
mv approved.new approved
sh update.sh
```

Запись в crontab оператора Docker обеспечивает применение новых одобренных версий:

```cron
*/5 * * * * /bin/sh /srv/agent-mobile/update.sh >> /srv/agent-mobile/update.log 2>&1
```

Укажите в PATH рабочего планировщика каталоги Docker и flock. Обновляется только
`mobile-web` в собственном Compose-проекте. Перед активацией проверяются читаемость
каталога и формат отпечатка. При ошибке запуска возвращается предыдущий digest из `active`;
при неудачной первой установке сайт останавливается. До расследования версия остаётся
в `failed`. Для ручного отката запишите прежний совместимый digest в `approved` и запустите
`update.sh`. Смена формата данных с потерей обратной совместимости требует отдельной миграции.

## Домен и проверка с телефона

Добавьте [виртуальный хост](nginx.conf.example) к HTTP-конфигурации nginx. Проверьте
`nginx -t` перед применением. Маршрут внешнего TCP 443 должен вести к nginx на TNAS.
Клиентский TLS действует для этого имени; nginx передаёт проверенный сертификат через
Unix-сокет. Контейнер работает без сети, PostgreSQL и Temporal для чтения снимка не нужны.

Проверьте с телефона выбор сертификата, список проектов, карточку и время статуса.
Отключите Mac, повторите чтение через мобильную сеть, затем обновите контейнер
и снова откройте ту же карточку. Отзовите отпечаток и проверьте HTTP 403. Для закрытия
входа отключите виртуальный хост. Состояние рабочих задач остаётся у Temporal.
